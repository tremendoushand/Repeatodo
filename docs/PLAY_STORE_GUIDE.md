# 구글 플레이스토어 판매 가이드

Repeatodo를 플레이스토어에 올려 무료 또는 유료로 판매하는 순서입니다. 2026년 10월 기준 정책을 바탕으로 썼어요. 구글 정책은 자주 바뀌니 Play Console 화면 안내를 함께 확인하세요.

## 0. 한눈에 보는 순서

1. 개발자 계정 만들기 (25달러, 1회)
2. 서명 키 만들기
3. 릴리스 빌드(AAB) 만들기
4. Play Console에 앱 만들기, 스토어 등록정보 작성
5. 앱 콘텐츠(정책) 설문 작성
6. **비공개 테스트 12명 이상 × 14일** (개인 계정 필수)
7. 프로덕션 출시 신청 → 심사 (보통 며칠)
8. 유료로 팔려면 판매자 계정(결제 프로필) 설정

## 1. 개발자 계정 만들기

- https://play.google.com/console 에서 가입, 등록비 **25달러(1회)**.
- 계정 유형 **개인**을 고르면 신분증 인증이 필요해요. 이름이 스토어에 개발자명으로 보일 수 있어요.
- **중요**: 2023년 11월 이후 만든 개인 계정은 프로덕션 출시 전에 **비공개 테스트에 테스터 12명 이상이 14일 연속 참여**해야 해요(6번).
- 기기 인증: Play Console 앱으로 실제 안드로이드 기기 확인을 요구할 수 있어요.

## 2. 서명 키 만들기

플레이스토어 앱은 **업로드 키**로 서명해서 올리고, 구글이 최종 **앱 서명 키**로 다시 서명해요(Play App Signing). 업로드 키를 잃어버리면 재발급 요청은 가능하지만 번거로우니 꼭 백업하세요.

```bash
keytool -genkeypair -v -keystore repeatodo-release.jks -alias repeatodo \
  -keyalg RSA -keysize 2048 -validity 10000
```

**로컬(Android Studio)에서 빌드할 때**: 프로젝트 맨 위에 `keystore.properties`를 만들어요. 이 파일과 `.jks`는 `.gitignore`에 들어 있어 GitHub에 올라가지 않아요.

```properties
storeFile=repeatodo-release.jks
storePassword=비밀번호
keyAlias=repeatodo
keyPassword=비밀번호
```

**GitHub Actions에서 빌드할 때**: 저장소 → Settings → Secrets and variables → Actions에 4개를 등록해요.

| 이름 | 값 |
|---|---|
| `REPEATODO_KEYSTORE_BASE64` | `base64 -w0 repeatodo-release.jks` 결과 (macOS는 `base64 -i repeatodo-release.jks`) |
| `REPEATODO_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
| `REPEATODO_KEY_ALIAS` | `repeatodo` |
| `REPEATODO_KEY_PASSWORD` | 키 비밀번호 |

그러면 Actions 실행 결과의 `repeatodo-release` 아티팩트에 서명된 `app-release.aab`와 `app-release.apk`가 생겨요.

## 3. 릴리스 빌드 만들기

- 출시할 때마다 `app/build.gradle.kts`의 `versionCode`를 1씩 올리고 `versionName`(예: `1.0.1`)을 바꿔요.
- Android Studio: **Build → Generate Signed App Bundle / APK → Android App Bundle**, 또는 터미널에서 `./gradlew bundleRelease`.
- 결과물: `app/build/outputs/bundle/release/app-release.aab` (플레이스토어는 AAB만 받아요).
- 대상 API: 이 앱은 targetSdk 36이에요. 구글은 매년 8월 말에 최소 대상 API를 올리니, 1년에 한 번 업데이트가 필요해요.

## 4. 앱 만들기와 스토어 등록정보

Play Console → **앱 만들기**: 앱 이름 `Repeatodo`, 기본 언어 한국어, 앱/게임 중 **앱**, 무료/유료 선택.

> **무료/유료는 신중히.** 한 번 무료로 출시하면 나중에 유료로 바꿀 수 없어요. 반대(유료→무료)는 가능해요.

스토어 등록정보에 필요한 것:

| 항목 | 규격 | 예시 |
|---|---|---|
| 앱 이름 | 30자 이내 | Repeatodo - 반복 할 일 체크 |
| 간단한 설명 | 80자 이내 | 매일·매주·매월 반복하는 할 일을 한 번에 체크하고 달성률을 확인하세요. |
| 자세한 설명 | 4000자 이내 | 아래 예시 참고 |
| 앱 아이콘 | 512×512 PNG | 런처 아이콘을 크게 내보내기 |
| 그래픽 이미지 | 1024×500 PNG/JPG | 앱 이름 + 화면 캡처 |
| 휴대전화 스크린샷 | 2~8장, 세로 9:16 권장 | 오늘, 대시보드(주간/월간), 할 일 편집, 설정 |
| 카테고리 | | 생산성 |
| 연락처 이메일 | 필수 | |
| 개인정보처리방침 URL | 필수 | 아래 5번 |

자세한 설명 예시:

```
매일 영양제, 매주 분리수거, 매월 카드값 확인처럼 반복되는 일을 잊지 마세요.

■ 탭 한 번으로 완료
오늘 할 일을 누르기만 하면 끝. 물 8잔처럼 여러 번 해야 하는 일도 탭할 때마다 숫자가 올라가요.

■ 원하는 대로 반복
매일 / 매주 원하는 요일 / 매월 원하는 날짜 / 말일 / "이번 주 안에 한 번"까지.
총 반복 횟수를 정하면 30일 챌린지처럼 다 채운 뒤 자동으로 끝나요.

■ 똑똑한 알림
시간을 정한 일은 그 시간에, 나머지는 원하는 시간에 남은 일만 모아서 알려줘요.
알림에서 바로 완료할 수 있어요.

■ 한눈에 보는 대시보드
주간·월간 달성률, 카테고리별 통계, 연속 달성 기록.

■ 캘린더와 구글 드라이브
폰 캘린더에 반복 일정으로 표시하고, 구글 드라이브로 기기 간 동기화하세요.

■ 회원가입 없음, 광고 없음
데이터는 내 폰과 내 구글 드라이브에만 저장돼요.
```

## 5. 앱 콘텐츠(정책) 작성

Play Console → **정책 및 프로그램 → 앱 콘텐츠**에서 모두 완료해야 출시할 수 있어요.

- **개인정보처리방침**: [PRIVACY_POLICY.md](PRIVACY_POLICY.md)에 연락 이메일을 넣고 공개 웹페이지로 올려요. 가장 쉬운 방법은 GitHub 저장소를 공개로 두고 파일 주소를 쓰거나, GitHub Pages / 노션 공개 페이지에 붙여넣는 거예요.
- **광고**: 광고 없음.
- **앱 액세스 권한**: 로그인 없이 모든 기능 사용 가능 (드라이브 동기화는 선택).
- **콘텐츠 등급**: 설문 작성 → 전체이용가 예상.
- **타겟층**: 만 18세 이상(또는 13세 이상). 어린이 대상이 아니라고 선택하면 정책 부담이 적어요.
- **데이터 보안** 설문 예시:
  - 데이터를 수집하나요? → 앱이 개발자 서버로 보내는 데이터는 없어요. 드라이브 동기화는 사용자 본인의 구글 계정으로 저장되는 것이라 "수집 없음"으로 답할 수 있지만, 확실히 하려면 *앱 활동 > 기타 사용자 생성 콘텐츠*를 "기기 간 동기화(앱 기능) 목적, 선택 사항, 전송 중 암호화"로 표시하는 편이 안전해요.
  - 데이터 공유: 없음. 데이터 삭제 요청: 앱 삭제 및 드라이브 숨겨진 데이터 삭제로 가능.
- **정확한 알람 권한(SCHEDULE_EXACT_ALARM)**: 이 앱은 사용자가 정한 시간의 할 일 알림이 핵심 기능이라 이 권한을 씁니다. 사용자가 직접 허용해야 하는 권한이라 별도 신고서는 보통 요구되지 않지만, 요청이 오면 "사용자가 설정한 할 일 알림 시간에 정확히 알리기 위함"이라고 적어요.
- **캘린더 권한**: 사용자가 켠 경우에만 할 일을 캘린더 일정으로 추가하기 위해 사용한다고 설명에 적어 둬요.

## 6. 비공개 테스트 (12명 × 14일)

1. **테스트 및 출시 → 테스트 → 비공개 테스트** → 트랙 만들기 → AAB 업로드.
2. 테스터: 이메일 목록(가족·지인 Gmail) 또는 구글 그룹을 등록해요. **최소 12명**.
3. 테스터에게 "참여 링크"를 보내면, 링크에서 테스트 참여 → 플레이스토어에서 설치.
4. **14일 동안 12명 이상이 계속 참여(설치 유지)** 하면 대시보드에서 **프로덕션 액세스 신청**이 열려요. 신청서에는 테스트 방법, 받은 피드백, 수정한 점을 적어요.
5. 사람을 모으기 어렵다면 개발자 커뮤니티의 "테스터 품앗이"를 활용하는 경우가 많아요.

## 7. 프로덕션 출시

- **테스트 및 출시 → 프로덕션 → 새 버전 만들기** → AAB 업로드 → 출시 노트 → 검토 → 출시.
- 처음엔 국가를 **대한민국**만 골라도 돼요.
- 심사는 보통 1~7일. 거절되면 이메일로 이유가 오고 고쳐서 다시 제출하면 돼요.
- 출시 후 Play Console → **앱 무결성**의 **앱 서명 키 SHA-1**을 [구글 클라우드 설정](GOOGLE_SETUP.md#4-안드로이드-oauth-클라이언트-만들기)에 추가해야 스토어 버전에서 드라이브 동기화가 동작해요.

## 8. 돈 받고 팔기

1. Play Console → **설정 → 결제 프로필**(판매자 계정) 만들기: 이름·주소, 정산 받을 **은행 계좌**, 세금 정보.
2. 판매 방식 중 하나를 골라요.
   - **유료 앱**: 앱 가격 설정(예: 1,500원~3,900원). 가장 간단하지만 무료 앱보다 다운로드가 훨씬 적어요.
   - **무료 + 앱 내 구매(추천)**: 기본 기능 무료, 예를 들어 "드라이브 동기화·캘린더 연동·위젯"을 프로 기능으로 1회 구매. 구글 Play 결제 라이브러리를 앱에 넣어야 해서 추가 개발이 필요해요(원하시면 만들어 드릴게요).
   - **광고**: AdMob 연동. 할 일 앱은 광고가 사용감을 해쳐 평점이 떨어지기 쉬워 추천하지 않아요.
3. **수수료**: 구글은 매출의 15%(연 매출 100만 달러까지)를 가져가요.
4. **세금**: 한국 사용자에게 판 금액의 부가세(10%)는 구글이 처리해요. 개발자가 받는 수익은 종합소득세 신고 대상이고, 계속 판매할 생각이면 사업자 등록(간이과세자, 업종 "응용 소프트웨어 개발 및 공급업")을 고려하세요. 정확한 내용은 세무사와 확인하는 게 좋아요.

## 9. 출시 후 관리

- **리뷰 답변**: Play Console → 평점 및 리뷰. 빠르게 답할수록 평점에 도움이 돼요.
- **비정상 종료**: Play Console → Android vitals에서 충돌 기록을 확인해요.
- **업데이트**: versionCode를 올려 새 AAB 업로드. 처음엔 단계적 출시(20% → 100%)를 쓰면 안전해요.
- **연 1회 대상 API 업데이트**: 매년 8월 말 마감 전에 targetSdk를 올려 다시 출시해요.

## 10. 출시 전 체크리스트

- [ ] `versionCode` / `versionName` 확인
- [ ] 서명 키 백업 (클라우드 + USB 등 두 곳 이상)
- [ ] 개인정보처리방침 웹페이지 공개, 연락 이메일 기입
- [ ] 스크린샷 2장 이상, 아이콘 512px, 그래픽 이미지 1024×500
- [ ] 구글 클라우드 OAuth에 Play 앱 서명 키 SHA-1 추가, OAuth 동의 화면 프로덕션 게시
- [ ] 실제 폰에서 알림, 재부팅 후 알림, 캘린더, 동기화, 백업/복원 확인
- [ ] 비공개 테스트 12명 × 14일 완료
